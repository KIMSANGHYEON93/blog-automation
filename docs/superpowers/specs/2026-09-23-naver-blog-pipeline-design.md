- 작성일: 2026-09-23
- 상태: 설계 승인 (구현 전)
- 선행 커밋: `09171c9` 네이버 BrowserPort 어댑터 (`src/infrastructure/browser/naver/`)

## 1. 목표와 결정 사항

티스토리 글을 복제하지 않고, **네이버 전용 키워드로 네이버 독자에 맞춘 글**을 따로 만들어
사람이 승인한 글만 발행한다.

| 항목 | 결정 | 이유 |
|------|------|------|
| 콘텐츠 출처 | 네이버 전용 키워드 | 티스토리와 주제가 겹치면 유사문서로 묶여 두 블로그 모두 순위가 떨어진다 |
| 주제 방향 | IT·AI 실무 (활용법·도구 비교·쉬운 개념 설명) | 네이버 검색 수요가 있고, AI-Brain 용어를 재사용할 수 있으며, C-Rank는 한 분야에 꾸준한 블로그를 높게 본다 |
| 발행 방식 | 대시보드에서 사람이 승인하면 자동 발행 | 자동 발행은 네이버 운영정책상 제재 위험이 커서 사람이 매 건 확인한다 |
| 생성 위치 | n8n 신규 워크플로우 | 기존 Pipeline A 노드를 재사용한다 |
| 저장 위치 | 같은 스프레드시트, 같은 컬럼 구조의 별도 탭 `naver_calendar` | Python 저장소·상태 머신·대시보드를 탭 이름만 바꿔 재사용하고, 티스토리 자동 발행이 네이버 글을 집어갈 수 없게 한다 |

## 2. 전체 흐름

```
[n8n] workflow_naver.json (매일 1회)
  naver_calendar 탭 '대기' 행
   → 네이버 검색 API(blog): 상위 글 5개 제목·요약 수집
   → Route Prompt (naver_e / naver_f / naver_g)
   → Gemini 생성 → 구조 검사(네이버 매개변수) → 교차 검증(naver_h)
   → naver_calendar 탭에 '발행대기' + 품질점수 기록

[사람] 관리자 대시보드 (python -m src.interface.web --platform naver)
   → 발행대기 글 목록·본문 검토 → '발행' 클릭
   → PublishSelectedPostUseCase (기존 그대로)
   → NaverBrowserAdapter(draft_only=False) → 글 URL과 logNo(entry_id)를 시트에 기록
```

- **키워드 입력**: 1단계에서는 사람이 `naver_calendar` 탭에 넣거나 AI-Brain 용어 탭에서 가져온다.
- **자동 발행 없음**: launchd에 네이버 발행 작업을 등록하지 않는다. 기존 티스토리 스케줄은 바꾸지 않는다.
- **SerpAPI 미사용**: 상위 글 수집은 네이버 검색 API(무료, 하루 25,000회)로 한다. 티스토리가 쓰는
  SerpAPI 한도(월 250회)를 나눠 쓰지 않는다.
- **발행량**: `naver_calendar`의 일일 쿼터는 1건이다.

### Python 변경 범위

| 변경 | 내용 |
|------|------|
| `GoogleSheetsPostRepository` | 선택 인자 `worksheet: str = ""` 추가. 비어 있으면 지금처럼 `sheet1`, 값이 있으면 그 이름의 탭을 연다 |
| `Config` | `NAVER_SHEET_TAB`(기본 `naver_calendar`), `NAVER_BLOG_ID` |
| 대시보드 `__main__` | `--platform naver`이면 저장소를 네이버 탭으로, 브라우저를 `NaverBrowserAdapter(draft_only=False)`로, 쿼터를 `QuotaManager(daily_limit=1)`로 바꿔 조립한다. `count_published_today()`는 저장소(탭) 기준이라 티스토리 발행 건수와 섞이지 않는다. 기본값은 `tistory`이며 현재 동작과 같다 |

상태 머신, `is_publishable()`(본문 3,000자 이상·품질 70점 이상), 일일 쿼터, 중복 키워드 규칙은 그대로 쓴다.

## 3. 품질 기준

### 3.1 생성 프롬프트 (`n8n/prompts/`, 기존 a~d는 수정하지 않음)

| 파일 | 대상 키워드 예 | 구조 |
|------|---------------|------|
| `prompt_naver_e_howto.md` | "노션 AI 사용법", "ChatGPT 엑셀 자동화" | 문제 상황 → 단계별 따라하기 → 자주 막히는 곳 → 정리 |
| `prompt_naver_f_compare.md` | "Claude vs ChatGPT 업무용" | 한줄 결론 → 비교표 → 상황별 추천 → FAQ |
| `prompt_naver_g_explain.md` | "MCP란", "RAG 쉽게" | 비유로 시작 → 핵심 개념 → 실무 예시 → 오해 바로잡기 |

`route_prompt`는 키워드 패턴으로 고른다. `vs`·`비교`·`차이`는 f, `란`·`뜻`·`개념`이나 AI-Brain 용어와 일치하는 키워드는 g, 나머지는 e.

### 3.2 네이버 규칙 (세 프롬프트 공통)

- **문체**: 해요체, 실무자 시점, 한 문단 2~3문장 (모바일 가독성)
- **경험 날조 금지**: "직접 써보니" 같은 거짓 1인칭 경험을 쓰지 않는다. 판단·팁 형태("이럴 때 주의하세요")로 쓴다.
  사람이 검토는 하지만 본문을 고치지 않고 발행하므로 생성 단계에서 막는다.
- **키워드**: 제목 앞부분에 1회, 본문에 자연스럽게 3~6회. 키워드 반복으로 채우지 않는다.
- **분량**: 본문 3,000자 이상 (기존 발행 규칙과 같음)
- **코드 블록 최소화**: SmartEditor 붙여넣기에서 코드 블록 표시가 검증되지 않았고, 독자층에도 맞지 않다
- **외부 링크**: 공식 문서만 3개 이하
- **태그**: 10개 안팎
- **차별 정보**: 프롬프트에 네이버 검색 상위 글 5개의 제목·요약을 넣고, 상위 글에 없는 정보를 1개 이상 요구한다

### 3.3 검증

1. **코드 검사**: `validate_structure.js`에 `platform: 'naver'` 매개변수를 추가한다. 아래 항목을 어기면 LLM 검증 없이 `검수필요`로 기록한다.
   - 문단 최대 길이
   - 키워드 반복 상한(6회)
   - 외부 링크 3개 이하
   - H2 3개 이상
2. **LLM 교차 검증** (`prompt_naver_h_verification.md`): 기존 d 항목(사실성·구조)에 아래 항목을 더한다. 통과 기준은 70점으로 같다.
   - 거짓 경험 포함 여부
   - 키워드 억지 삽입
   - 상위 글 대비 차별 정보
   - 모바일 가독성

### 3.4 중복 방지

`Check Duplicate` 노드가 `naver_calendar`와 티스토리 탭의 발행 키워드를 **모두** 확인한다.
키워드 출처는 달라도 분야가 같아 주제가 겹칠 수 있다.

### 3.5 1단계 범위 밖

- 이미지: 외부 이미지 URL 붙여넣기가 네이버에 업로드되는지 검증되지 않았다. 텍스트 글로 먼저 운영한다
- 검색광고 API 기반 키워드 자동 발굴
- 글 수정(`update`)

## 4. 오류 처리

| 상황 | 처리 |
|------|------|
| 네이버 검색 API 실패 (n8n) | 2회 재시도 후 `검수필요`와 사유를 기록한다. 상위 글 없이 생성하지 않는다 |
| LLM 응답 잘림 | 생성·검증 모두 `maxTokens` 4096 이상. 실행 로그의 `finishReason`을 확인한다 |
| 검증 70점 미만 | `검수필요` (기존과 같음) |
| 네이버 세션 만료 | `login()`이 False → `LoginFailedError` → 텔레그램 알림. 대시보드 작업 화면에 `naver_blog.py login` 재실행을 안내한다 |
| 본문 붙여넣기 실패·DOM 변경 | `NaverEditorError` → `발행실패`, `logs/naver/`에 스크린샷을 남긴다 |
| **발행 확인 클릭 후 URL 확인 실패** | 실제로는 발행됐을 수 있다. 사유에 "발행 여부 수동 확인 필요"를 적고 자동 재시도하지 않는다. `--recover-failed`는 티스토리 탭만 보므로 네이버 탭에는 적용되지 않는다 |

## 5. 테스트

- **Python (TDD)**: 저장소 `worksheet` 인자, 설정값, 대시보드 `--platform naver` 조립, 어댑터(16건 작성 완료). `make quality` 통과
- **n8n**: 코드 노드마다 `node --check`, 네이버용 구조 검사는 node 스크립트로 입출력을 확인, 워크플로우는 수동 실행으로 1행 검증
- **실측**: `scripts/naver_blog.py draft`로 임시저장을 시험한 뒤 실제 발행 1건

## 6. 구현 순서

0. **사전 준비 (사용자)**
   - 네이버 개발자센터 앱 등록 → 검색 API Client ID/Secret 발급, n8n 자격증명 등록
   - `.env`에 `NAVER_BLOG_ID` 추가
   - `python scripts/naver_blog.py login`
   - 시트에 `naver_calendar` 탭 추가 (1행 헤더는 기존 탭에서 복사)
1. **에디터 실측**: `draft` 시험으로 붙여넣기 방식과 셀렉터를 확정한다. 합성 paste 이벤트가 먹히지
   않으면 실제 클립보드 방식으로 바꾼다. 결과에 따라 나머지 설계가 달라질 수 있어 가장 먼저 한다.
   - 소제목(h2)·표·목록이 SmartEditor 컴포넌트로 바뀌는지도 이때 확인한다
2. **Python 연결**: 저장소 `worksheet` 인자, 설정, 대시보드 `--platform naver`
3. **n8n**: 프롬프트 4종, `workflow_naver.json`, 구조 검사 매개변수, 중복 검사 두 탭 확장
4. **E2E**: 키워드 3개 → 생성 → 대시보드 검토 → 1건 발행
5. **2단계 (별도 설계)**: 검색광고 API 키워드 발굴, 이미지 업로드, 글 수정

## 7. 위험

- **계정 제재**: 사람이 승인해도 발행 행위는 자동이다. 하루 1건 쿼터와 사람 검토로 위험을 낮추지만 없앨 수는 없다.
- **DOM 변경**: 네이버가 에디터를 바꾸면 발행이 멈춘다. 셀렉터는 `naver/selectors.py` 한 곳에 모아 두었다.
- **n8n 코드 동기화**: `code_nodes/*.js`와 워크플로우 JSON의 `jsCode`는 자동 동기화되지 않는다.
  두 곳을 함께 고치고 `node --check`로 확인한다 (CLAUDE.md 참고).
